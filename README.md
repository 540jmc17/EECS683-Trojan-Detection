### How the Netlist Parser Works

The parser follows several main steps.

**Step 1: Read the Verilog File**

The program locates the selected Verilog file and reads its contents.

It removes comments before analyzing the circuit so that commented-out gates are not accidentally counted.

**Step 2: Identify the Main Circuit Module**

The program searches for the main Verilog module.

For example:

- The baseline `s27.v` circuit uses the module name `s27`.
- The instructor's `design8.v` and `design48.v` circuits use the module name `top`.

The parser also avoids confusing a helper flip-flop module with the main circuit.

**Step 3: Identify Inputs, Outputs, and Wires**

The program reads signal declarations to identify:

- Primary inputs
- Primary outputs
- Internal wires
- Individual bits of multi-bit signals

For example, a two-bit signal named `n4` may contain:

- `n4[0]`
- `n4[1]`

The parser records these as individual bit-level signals.

**Step 4: Identify Logic Gates**

The program recognizes supported primitive logic gates, including:

- AND
- OR
- NAND
- NOR
- NOT
- XOR
- XNOR
- BUF

For every recognized gate, the parser records:

- Gate instance name
- Gate type
- Output signal
- Input signals

For example, consider the following Verilog statement:

```verilog
nand g0(n45, n4[0], n38);
```

The parser identifies:

- Gate type: NAND
- Gate name: g0
- Output: n45
- Input 1: n4[0]
- Input 2: n38

This information describes how the gate is connected within the circuit.

It does not calculate fan-in, fan-out, or other security-related features.

**Step 5: Identify Flip-Flops**

The parser also identifies supported D flip-flop instances.

Flip-flops store circuit values between clock events.

The parser records their connections, including:

- Clock (CK)
- Data input (D)
- Output (Q)
- Additional connections such as reset (RN) and set (SN)

The parser supports the positional flip-flop connections found in `s27.v` and the named-port connections found in the instructor's circuits.

**Step 6: Collect Unique Nets**

The program collects signal names from the circuit declarations and component connections.

It removes duplicate names so that each unique net appears once in the final list.

Constant logic values, such as `1'b0`, are not counted as separate nets.

**Step 7: Export Circuit Information**

After the circuit has been parsed, the program organizes the extracted information into a Python dictionary.

It can then save that information as a JSON file.

This allows other team members to use the circuit connectivity without having to manually examine every Verilog gate.

### How to Run the Parser

Open the `EECS683-Trojan-Detection` project folder in VS Code.

Open a terminal in the main project directory.

Python 3 is required. The parser itself uses Python's standard library.

To analyze the smaller instructor circuit, run:

```bash
python3 src/netlist_parser.py design8.v
```

To analyze the larger instructor circuit, run:

```bash
python3 src/netlist_parser.py design48.v
```

These commands display a summary of the circuit.

The summary includes:

- Circuit filename
- Module name
- Number of primary input bits
- Number of primary output bits
- Number of logic gates
- Number of flip-flops
- Number of unique nets

### How to Generate JSON Output Files

The parser can also save the extracted circuit information into JSON files.

For `design8.v`, run:


For `design48.v`, run:


The generated files will be stored in the `outputs/` folder.

These files contain the extracted circuit connectivity information.

They can be used by team members who are calculating structural features, security features, and performing Trojan detection.

### Understanding the JSON Output

The `parse_netlist()` function returns a dictionary containing the extracted circuit information.

The main fields are:

| Field | Description |
|---|---|
| `source_file` | Name of the Verilog file |
| `module` | Main circuit module |
| `primary_inputs` | Primary input signals |
| `primary_outputs` | Primary output signals |
| `wires` | Declared internal wires |
| `gates` | Logic gate instances and their connections |
| `flip_flops` | Flip-flop instances and their connections |
| `nets` | Unique circuit signal names |
| `summary` | Basic circuit component counts |

The gate information can be used by other team members to calculate structural features.

For example, the parser identifies which signals enter and leave a particular gate.

Another team member can then use those connections to calculate fan-in, fan-out, and additional structural properties.

### Supported Format and Limitations

The Netlist Parser is designed to work with supported gate-level Verilog circuits.

It currently supports:

- Basic primitive logic gate instances
- Scalar wires and signals
- Individual bus bits
- Supported Verilog constants
- Positional D flip-flop connections
- Named-port D flip-flop connections
- The circuit formats used in the current project tests

The parser is not a complete Verilog compiler.

More advanced or behavioral Verilog statements may require additional functionality.

For example, unsupported cell types, `assign` statements, and other Verilog constructs may not be processed by the current parser.

Unsupported statements should produce an error instead of silently ignoring circuit logic.

If additional circuit files are provided by the instructor, their syntax and extracted results should be tested before using them for further analysis.
